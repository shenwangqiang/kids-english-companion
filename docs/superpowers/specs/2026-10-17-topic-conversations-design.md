# Topic Conversations and Multi-Session History Design

Date: 2026-10-17

## Goal

Extend Kids English Companion so a child can start age-appropriate English conversations around familiar topics such as *How to Train Your Dragon* or *Harry Potter*, revisit earlier conversations, start a clean conversation, and tap a message to hear it again. The app remains portrait-only and continues to use the configured Mac-hosted Ollama model.

## Scope

This change includes:

- portrait-only activity orientation;
- tappable conversation bubbles that replay their English text through the configured TTS engine;
- a curated topic picker plus a custom-topic option;
- topic-aware prompts that guide the conversation without reproducing book text;
- multiple persisted conversations per age band;
- a conversation history screen and a new-conversation action;
- database migration that retains existing conversations;
- emulator-based automated and smoke verification.

This change does not include copyrighted book text, ebook import, DRM handling, cloud history, account sync, web search, or publisher integrations.

## Topic Conversation Behavior

The initial topic catalog contains:

- How to Train Your Dragon;
- Harry Potter;
- Space;
- Dinosaurs;
- Animals;
- School Life;
- Custom Topic.

Starting a topic creates a new conversation session. The first assistant turn is generated by the model, not hard-coded, so its language can match the selected age band. The prompt instructs the model to:

- use age-appropriate English;
- briefly acknowledge the child's previous answer;
- ask exactly one natural next question;
- remain on the selected topic unless the child clearly changes it;
- discuss characters, themes, preferences, vocabulary, and a child's own recollection;
- avoid long quotations, reconstructed chapters, page-by-page narration, or claims that the app contains the source books;
- state uncertainty naturally and ask the child what happened when an exact story detail is uncertain;
- avoid spoilers unless the child introduces the relevant event.

The model's pretrained knowledge may be incomplete. The UI therefore describes branded-book topics as conversation topics rather than authoritative book guides.

## Conversation Sessions

Each conversation session contains:

- a unique session ID;
- age band;
- selected topic ID and display title;
- an automatically generated session title;
- summary, remembered facts, and next direction;
- creation and update timestamps;
- ordered user and assistant turns.

The session title is derived locally from the first user message. If no user message exists, the topic title is used. Titles are trimmed to a short single line and do not require an additional model request.

The current session is tracked independently for each age band. Creating a new session changes the active session without deleting the previous one. Opening a history item makes that session active and restores its messages and memory.

Existing fixed sessions such as `conversation-6-8` are migrated in place and remain accessible as the initial history entry for their age band. Existing turns, summaries, and remembered facts are retained.

## History Interface

The conversation screen header adds:

- `New Conversation`;
- `History`;
- the existing stories, progress, and settings actions.

`New Conversation` opens the topic picker. Choosing a predefined topic immediately creates and opens a session. Choosing `Custom Topic` reveals a bounded text field before creation.

The history screen lists sessions for the selected age band, newest first. Each row shows:

- session title;
- topic;
- last updated time;
- a short preview from the most recent turn.

Selecting a row returns to the conversation screen with that session active. Session deletion, rename, search, and cloud sync are intentionally deferred.

## Tap-to-Replay

Every user and assistant conversation card is tappable. A tap:

1. stops any current TTS utterance;
2. reads the selected message through the persisted `Automatic / Google / iFlytek` preference;
3. uses the existing child-conversation voice style;
4. does not start microphone recognition or the continuous lock-screen voice loop.

The conversation screen displays a concise hint that messages can be tapped to replay. Blank or non-English system labels are never sent to TTS.

## Data Model and Migration

The Room database version increases from 2 to 3.

`conversation_sessions` gains:

- `topicId TEXT NOT NULL DEFAULT 'general'`;
- `topicTitle TEXT NOT NULL DEFAULT 'General Conversation'`;
- `title TEXT NOT NULL DEFAULT ''`.

DAO additions provide:

- observation of sessions by age band ordered by `updatedAt DESC`;
- observation of a specific session and its turns;
- lookup of the latest turn preview;
- title and topic updates.

The repository API becomes session-oriented. It accepts explicit session IDs for observing turns, appending user messages, and applying model outcomes. It also exposes history and new-session operations. Active session IDs are persisted in DataStore by age band; when no active value exists, the repository uses the most recently updated migrated session or creates a general session.

Foreign-key cascade behavior remains unchanged.

## Prompt and Context Flow

`ConversationRequest` gains topic metadata. `ConversationPrompt` includes the selected topic in the system message and retains the existing summary, remembered facts, recent-turn limit, reply word limits, and one-question rule.

Only recent conversation turns and compact memory are sent to Ollama. Conversation history entries not belonging to the active session are never included, preventing cross-session context leakage and unnecessary latency.

## Portrait Orientation

`MainActivity` declares portrait orientation in the Android manifest. Activity recreation remains supported for process death and configuration-independent lifecycle events, but physical rotation does not move the learning UI into landscape.

## Error Handling

- If Ollama is unavailable while creating the first assistant topic message, the new session remains saved and can be retried.
- If TTS is unavailable, the existing localized TTS error is shown without altering the conversation.
- An empty or oversized custom topic is rejected locally.
- If the saved active session no longer exists, the app selects the newest remaining session or creates a general session.
- Database migration is additive and does not delete existing conversation data.

## Verification

Development follows red-green-refactor tests covering:

- Room migration retains legacy sessions and turns;
- independent sessions never share messages or memory;
- new conversation creation and history ordering;
- active-session fallback behavior;
- topic prompt safety and age-appropriate constraints;
- local title generation;
- message-card click invokes replay without starting recognition;
- topic picker, history navigation, and session restoration in Compose tests;
- manifest portrait declaration;
- existing model discovery, voice, reading, and conversation tests continue to pass.

Final verification uses the Android emulator because the OnePlus device is offline. It includes unit tests, lint, debug assembly, connected instrumentation tests, app launch, topic-session creation, message replay invocation, history reopening, screenshots, and crash-log inspection.
